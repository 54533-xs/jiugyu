# 悬浮聊天与记忆优化

本轮工作范围：

- 悬浮聊天窗口的输入区、功能面板与软键盘适配。
- 主号与小号按独立身份保存聊天和记忆，模型只接收昵称。
- 小号编辑和删除，绑定关系仅用于收纳。
- 记忆页面统一搜索标签、内容、昵称和会话。
- 角色记忆列表分段加载。
- 聊天发送与重新生成的界面响应和上下文处理优化。

实现说明：

- 真实会话按账号独立保存；角色短期记忆汇总所有相关会话，以昵称区分联系人，不发送主号/小号标签。
- 新消息保存发送时的昵称，旧消息根据所属会话解析。身份编辑不会修改历史消息，小号删除保留历史资料供记忆读取。
- 记忆首页先显示角色，后台只补充数据库计数；进入详情才分批组装时间线。搜索覆盖全部已加载记录，最多渲染最近 2000 条匹配结果。
- 消息读取按会话建立位置索引，避免重复扫描其他会话。私聊不再重复组装当前会话；群聊复用已组装的角色时间线。
- 点击生成后先绘制状态，再处理上下文；长聊天记录组装按批次让出主线程。
- 悬浮聊天采用标题、可伸缩消息区域、底部输入区的布局，扩展输入区域可在窗口内滚动。

验证：类型检查、生产构建、385 个现有提示词场景、SDK/推送一致性检查、身份与索引专项回归。

测试重点：手机软键盘展开与功能面板；大数据账号发送/重试响应；小号改名、删除和切换后的记忆昵称。实际 API 等待时间仍由接口决定。

PR 保持开放，供真机测试。
